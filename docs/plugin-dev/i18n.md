# 多语言

站点的界面文案走同一套机制：**键就是英文原句**，运行时按访客语言查词典，查不到就显示原句。
核心有 25 种语言（`locales/*.json`），插件的词条放自己的 `i18n/`。

## 代码里怎么写

```php
echo t('Bookmarks');                                   // 简单一句
echo t('Saved by {:name}', ['name' => $username]);      // 带参数
echo t('Welcome to {:sitename}', []);                   // {:sitename} 全局占位符，不用传
```

模板里：

```php
<h1><?= htmlspecialchars(t('Bookmarks')) ?></h1>
```

三条规矩：

1. **键是完整的英文句子**，不是一个标识符。写 `'Bookmarks'`，不写 `'bookmarks.title'`。
   译者拿到的是句子本身，脱离代码也知道在说什么。
2. **占位符用 `{:名字}`**，参数用关联数组传。`--check` 会核对原文和译文里的占位符是否一致，不一致就报错。
3. **词典内容要转义**。`t()` 返回的是原文，有些键里带 `<a>`（核心就有），所以别整体 `htmlspecialchars()` 掉；
   要转义的是插进去的参数和用户输入。

`{:sitename}` 会自动换成站点名，调用点不用传，翻译时也别把它翻掉。

## 插件的词典

```
plugins/example/i18n/
├── en.json        键 = 值（母键，英文原句）
├── zh-hans.json   英文键 → 中文译文
├── zh-hant.json
└── ...            核心支持的 25 种语言各一份
```

格式是扁平的 JSON：

```json
{
  "Bookmarks": "Bookmarks",
  "Saved by {:name}": "Saved by {:name}"
}
```

运行时的查找顺序：当前语言的**核心词典** → 当前语言的**插件词典** → 英文核心词典 → 英文插件词典 → 原句。
所以插件的键不会盖掉核心的同名键，也不用重复核心已有的词条。

## 清单里的文案也算键

`plugin.json` 的 `description`、`specialPages.title`、`adminPages.title` / `description` 渲染时都过 `t()`，
所以它们也是键，也要进词典：

```json
"description": "A starting point for a Nomen plugin: one special page, one hook, one stylesheet."
```

```json
{"A starting point for a Nomen plugin: one special page, one hook, one stylesheet.": "写 Nomen 插件的起点……"}
```

## 25 份文件，缺一份就红

`extract.php` 会扫插件目录里的 `t('...')` 调用和清单文案，然后要求 `i18n/` 下**每种语言都有一份文件、每个键都在**。
没翻译的语言可以先填英文，但不能缺文件。

新加一条文案的最小流程：

```bash
# 1. 代码里写 t('English sentence.')
# 2. 生成/补齐词典（只新增，不动已有）
php docs-internal/i18n/extract.php
# 3. 验收
php docs-internal/i18n/extract.php --check
```

`--check` 输出 `检查通过：N 个域、M 个键，每个语言文件都齐全。` 才算过。它同时会报：

| 提示 | 意思 |
|---|---|
| `[缺] 代码里有、核心en 没有` | 新写的键没进 `en.json` |
| `[悬] 核心en 有、代码里扫不到` | 改了文案但旧键还留着；确认后删掉 |
| `[缺条目] <语言> <键>` | 这份语言文件少了这一条 |
| `[占位符不一致]` | 原文有 `{:name}`，译文里没有（或反过来） |

**旧的键别顺手改措辞。** 改一个键等于 25 个语言文件全动一遍，而且译文的对应关系会断。要改就在新键上改，
旧的标成悬空后删。

## 扫描的边界

`extract.php` 只认**字面量参数**：

```php
t('Bookmarks');                 // 收得到
t($label);                      // 收不到
tIn('zh-hans', $x ?? $y);       // 第二参是表达式，收不到，还会把 'zh-hans' 当成键
```

所以文案别用变量拼，直接写字面量。后台那种固定中文的界面用 `tIn('zh-hans', ...)` 时，第二个参数保持纯变量。

## 前端和独立入口

- 前端词典走 `/i18n/<语言>`，核心会把插件 `i18n/` 里的词条一并给出去，Vue / JS 里照常 `t()`。
- 安装向导那种独立入口用 `nomen_install_t()`，键同样是英文原句。
- 邮件模板的键在 `src/EmailTemplate.php` 里单独收，不按普通调用点扫。

## 别做的事

- **别在插件里读 `locales/`。** 那是核心文件，路径和格式都可能变；用 `t()`。
- **别按语言分支写逻辑。** 想要「中文站显示 A，英文站显示 B」就用不同的键加 `t()`，不要 `if (locale === 'zh-hans')`。
- **别把用户输入直接塞进键。** 键是固定的，参数走 `{}`。
