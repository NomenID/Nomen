# 错误处理

原则只有一条：**报错这一步自己不能再炸**。所以错误页不读语言包、不读皮肤、不查数据库——这三样任何一样坏了，
你还能看到一句人话，而不是白屏。

## 报错页

`src/ErrorPage.php` 负责全部出口：

| 入口 | 触发 |
|---|---|
| `Response::error($code, $message)` | 控制器主动报错 |
| `set_exception_handler` | 未捕获的异常 |
| `register_shutdown_function` | 真正的致命错误（内存耗尽、解析错误） |

它会先把缓冲里半截的 HTML 全部丢掉再渲染，所以不会出现「页面渲染到一半 + 底下一段红字」。

`Response::error()` 支持的码：`400` `403` `404` `405` `429` `500` `503`。插件里直接调用就行：

```php
Response::error(404);                                  // 最常用：不告诉对方这条存不存在
Response::error(403, 'You cannot edit this page.');    // 明确拒绝
```

**越权一律 404，不要 403**：403 等于确认「这条记录存在」，可以被用来试探。

## 500 的编号

500 以上会生成一个 8 位十六进制编号，同时写进错误日志和页面上：

```
[nomen] [3f9a1c7e] error 500 @ /admin/users
[nomen] [3f9a1c7e] RuntimeException: ... in /www/wwwroot/x/src/Foo.php:42 @ /admin/users
```

让用户把这个编号报给你，`grep 3f9a1c7e` 就能定位到那一次。4xx 不生成编号（那是正常的拒绝，不是故障）。

## APP_DEBUG

`.env` 里 `APP_DEBUG=1` 时，500 页面会带上异常类型、消息、文件行号和调用栈；关掉只显示编号。

**线上永远别开。** 它会暴露文件路径和内部结构。本地调试开着方便，交付前检查一遍：

```bash
grep -i '^APP_DEBUG' .env    # 线上应该没有这一行，或者 =0
```

## 日志

统一走 `error_log()`，写进 PHP-FPM 的错误日志（宝塔是 `/www/wwwlogs/<域名>.error.log`）。
带方括号前缀，方便 grep：

| 前缀 | 来源 |
|---|---|
| `[nomen]` | 核心报错 |
| `[Plugins]` | 插件加载、钩子注册 |
| `[SECURITY]` | pepper 没配这类配置问题 |
| `[Session]` / `[redis]` | 会话后端回退 |

插件里调试也照这个写：

```php
error_log('[example] hook fired: ' . __FUNCTION__);
```

**别把用户数据写进日志**：邮箱、IP 之外的隐私、令牌、密码哈希都不要。日志会被运维看到、会被备份、会被贴出来。

## 常见错误码

| 码 | 什么时候用 |
|---|---|
| 400 | 参数不合法（不是缺 CSRF，那走 419/403 的语义自己定） |
| 403 | 明确知道对方是谁、但没权限 |
| 404 | 资源不存在，或者不想让对方知道存不存在 |
| 405 | 方法不对（GET 接口被 POST） |
| 429 | 限流（响应头带 `Retry-After`） |
| 500 | 代码/配置出问题 |
| 503 | 维护中、依赖不可用 |

## 白屏 / 半截页面

| 现象 | 先看什么 |
|---|---|
| 纯白，无任何输出 | PHP 致命错误被 shutdown 接住了，但日志里应该有 `[nomen] [xxxx]` |
| 半截页面 + 后面断了 | 模板里 `require` 了不存在的文件，或者 `exit` 提前退出 |
| 500 但日志里没有 `[nomen]` | 可能是 nginx / php-fpm 层的错（502、连接被拒），不是 PHP |
| 中文全变成问号 | 数据库连接没设 utf8mb4，或者文件本身不是 UTF-8 |

`php -l` 只能查语法；运行时错误（调不存在的方法、类型不匹配）要靠日志。PHP 8 对类型很严格，
`$x ?? ''` 这类兜底在该有的时候必须有。

## 报错页的自定义

`ErrorPage` 的样式和文案是内置的，**不走皮肤**（皮肤坏了也能显示）。想改只能改 `src/ErrorPage.php`——
公开发布的项目里这不推荐，因为升级会覆盖。真要品牌化，改的是那里的静态字符串，别接数据库。

## 检查清单

- [ ] 线上 `APP_DEBUG` 关着
- [ ] 新增的 `Response::error()` 用的是合适的码（别一律 500）
- [ ] 越权返回 404
- [ ] 500 的编号能在日志里搜到
- [ ] 日志里没有口令、令牌、私钥
