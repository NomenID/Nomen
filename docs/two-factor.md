# 两步验证

两个层级：站点策略（后台）和用户策略（设置页）。**同时生效，取更严格的那个**。

## 站点策略

后台「设置」→「登录两步验证」，存在 `site_settings` 的 `security.login_2fa`：

| 值 | 行为 |
|---|---|
| `off`（默认） | 不做第二步验证 |
| `new_device` | 当前设备不是可信设备时才要第二因素 |
| `every_login` | 每次登录都要 |

**打开之前确认两件事**：站点配了 SMTP，或者用户已经配了 TOTP。否则用户可能一个可用的第二因素都没有
——那种情况下系统会放行（见下面「降级」），等于白开。

## 用户策略

设置页可以选「仅新设备验证」或「每次登录都验证」（`POST /settings/two-factor/policy`）。

选「每次登录都验证」时，账号必须至少有一个可用的第二因素，否则**后端拒绝保存**——避免把自己锁在门外。

站点策略是 `off` 时，用户策略不生效。

## 四种第二因素

第一因素已经用过的类型不会再出现（用密码登录的，第二步不会再要密码）。

| 因素 | 条件 | 存在哪 |
|---|---|---|
| 邮箱验证码 | SMTP 可用 + 账号有已验证邮箱 | 无（临时码走会话） |
| 验证器 APP（TOTP） | 用户在设置页启用 | `user_totp_secrets` |
| 恢复码 | 生成过且还有没用掉的 | `user_recovery_codes` |
| 密码 | 第一因素不是密码时才可用 | `users.password_hash` |

### 降级：一个可用因素都没有就放行

这是**有意设计**，不是漏洞：站点开了 `every_login` 但用户既没配 TOTP、也没邮箱、也没有恢复码，
硬拦就是把人锁死。所以这种情况直接放行。

代价是：**开了站点级二验不等于每个人都受保护**。要真保护就用 TOTP 或强制邮箱验证。

## TOTP 设置

设置页 →「两步验证」→「验证器 APP」：

1. 服务端生成密钥和 `otpauth://` 链接（`/2fa/totp/setup`）。
2. 页面显示二维码（装了 `totp-qr` 插件就在浏览器里画）和手动输入的密钥。
3. 用户输入 6 位动态码，`/2fa/totp/verify` 验证通过后 `verified = 1`，正式启用。
4. 关闭（`/2fa/totp/disable`）同样要确认身份。

同一个账号只保留一条记录。密钥在 `user_totp_secrets`，**删掉这一行等于关掉二验**。

## 恢复码

```bash
# 生成（需要密码确认）
curl -X POST https://你的站点/2fa/recovery-codes/generate -b cookie.txt -d "_csrf=<token>"
```

- 一次 8 个，每码 12 位，**只显示一次**。
- 生成新批次会删掉旧批次。
- 每个码只能用一次，用掉后写 `used_at`。
- 生成和删除都要求输入密码；账号恢复模式下跳过（旧密码正是问题所在）。

恢复码**只是登录时的第二因素**，不是账号找回。账号彻底进不去时走 [账号恢复](recovery.md)。

## 待验证会话

第一因素通过、需要第二因素时写一个 `2fa_pending` 会话，有效期 `two_factor_pending_ttl`（默认 600 秒）。
超时或换浏览器都要重新登录。

这个会话还带着账号快照：在二验页点「无法验证」会带着它进申诉流程，用户不用再填一遍用户名和邮箱。

## 登录时的完整链路

```
POST /login
  ├─ 密码正确、站点策略 off        → 建会话，完成
  ├─ 需要第二因素
  │    ├─ 有 TOTP        → /2fa/verify（输码）
  │    ├─ 有邮箱         → /2fa/verify（发码）
  │    ├─ 有恢复码       → /2fa/verify（输恢复码）
  │    └─ 一个都没有     → 放行
  └─ 密码错误            → 记一次失败，超阈值要验证码
```

## 坑

- **站点开了 `every_login` 但没人配 TOTP**：等于没开。
- **SMTP 挂了，邮箱验证码这条就断了**：用户只剩 TOTP 或恢复码。
- **恢复码一次性显示**：用户没存就只能重新生成，而重新生成要登录——锁死人。
- **`two_factor_pending_ttl` 太短**：用户输码慢一点就超时，表现是「明明输对了又跳回登录页」。

## 检查清单

- [ ] 打开站点策略前，确认 SMTP 可用或有用户配了 TOTP
- [ ] 至少一个管理员账号配了 TOTP 并保存了恢复码
- [ ] `/2fa/verify` 页面能正常出二维码
- [ ] 恢复码生成后立刻保存（只显示一次）
- [ ] 关闭二验需要确认身份
