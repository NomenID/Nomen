# 管理后台

`/admin` 是后台入口。界面是 Vue 单页，数据走 `/api/admin/*`，但**插件页面仍然是服务端返回 HTML**，
由外壳塞进面板里。

## 侧栏

| 菜单 | 地址 | 干什么 |
|---|---|---|
| 概览 | `/admin` | 统计、版本、最近活动、插件状态 |
| 首页 | `/admin/homepage` | 首页模式、标题、按钮、底部链接 |
| 用户 | `/admin/users` | 列表、搜索、启停、改角色、看详情 |
| 应用 | `/admin/apps` | OAuth 应用：建、改、重置 secret、删 |
| 登录方式 | `/admin/identities` | 五种登录开关、第三方提供方管理 |
| 接入点 | `/admin/mounts` | 插件占的公开地址，能改路径 |
| 恢复工单 | `/admin/recovery` | 申诉审核 |
| 活动日志 | `/admin/logs` | 登录与操作记录，可导出 CSV |
| 设置 | `/admin/settings` | 两步验证策略、缓存后端、站点 API 开关 |
| 插件自带 | `/admin/<slug>` | 插件注册的页面，挂在「内容」这类分组下 |

插件页由 `adminPages` 或 `Admin::page()` 注册，菜单文字和分组由插件给。

## 用户页

- 列表按 UNID 展示——**界面上不出现自增 id**。
- 能搜用户名 / 邮箱 / UNID。
- 单行操作：禁用 / 启用、设为管理员 / 取消管理员。这两个动作会发 `admin.user.status_changed` 和
  `admin.user.role_changed` 钩子。
- 详情页：资料、邮箱列表、设备、二验状态、第三方绑定、最近活动。
- 导出 CSV 的列名用的是「编号 / 操作者编号 / 目标编号」，值都是 UNID。

## 应用页

建应用要填：名称、回调地址（多个用换行）、scopes、是否强制 PKCE。

- `client_secret` **只显示一次**，之后只能重置。
- 重置 secret 会让旧 secret 立刻失效。
- 删应用**不撤销已发出的令牌**（令牌到期自然失效）。

## 活动日志

记录登录、改密码、后台操作、二验变动这些。可以按动作、分类、时间筛。

**不要往里写敏感值**：密码、令牌、密钥都不行，日志会被导出和备份。`ActivityLog` 里有一份字段黑名单，
插件写日志时也要避开这些。

## 设置页

| 分区 | 能改什么 |
|---|---|
| 登录两步验证 | `off` / `new_device` / `every_login` |
| 缓存 | `auto` / `redis` / `file` / `db` |
| 站点 API | 总开关 |
| 首页 | 模式、标题、副标题、按钮、链接 |
| 登录方式 | 五种方式的开关 |

改动立刻生效（存 `site_settings`，下一次请求就读库）。

## 恢复工单

审核页能看到用户填的资料、证明材料、和库里的比对结果、账号现有可用因素。通过后发一次性链接。

细节见 [账号恢复](recovery.md)。

## 盲区

- **后台不显示自增 id**：排查时要用 UNID，别在数据库里拿 id 对。
- **插件页的样式**：用 `a-*` 那套类，别自己写一套（会和后台主题打架）。
- **后台不做移动端适配**：手机上勉强能用，正经操作还是桌面。
- **后台的多语言**：界面固定中文（`tIn('zh-hans', ...)`）。这是有意设计，不是漏翻。
- **后台缓存**：`/api/admin/*` 不缓存，每次都是实时数据。

## 检查清单

- [ ] 管理员账号至少两个（一个锁死还有另一个）
- [ ] 恢复工单有明确的审核流程（谁审、多快）
- [ ] 活动日志有保留策略（别无限涨）
- [ ] 插件页在后台能正常显示
