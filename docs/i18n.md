# 多语言

界面自带 25 种语言：`ar` `bn` `de` `el` `en` `es` `fa` `fr` `he` `hi` `id` `it` `ja` `ko`
`ms` `nl` `pl` `pt` `ru` `th` `tr` `uk` `vi` `zh-hans` `zh-hant`。

## 语言怎么选

按顺序，命中一个就停：

1. `?lang=<语言>` 参数（显式选择）
2. 登录账号里存的偏好
3. cookie `nomen_lang`
4. 浏览器 `Accept-Language` 能匹配上的语言
5. 站点默认语言

站点默认语言是 `config/installed.php` 的 `app.language_default`，也可以用环境变量 `APP_LANGUAGE` 覆盖。
安装向导「站点」一步会问。

`app.language_allow_switch`（默认 `true`）关掉后，全站固定默认语言：语言选择器、`?lang=`、
账号语言偏好全部停用。

## 切换入口

- 页头的语言选择器。没有 JS 时是一个普通链接，指向 `/special/lang`；有 JS 才升级成下拉。
- `/special/lang?select=<语言>&rt=<返回地址>`：写入 cookie / 账号偏好后 303 回来源页。
  `rt` 只接受本站路径。
- 页面源码里不出现 `?lang=` 链接，便于搜索引擎抓取统一地址。

## 词典规则

- **键 = 英文原句**。`locales/en.json` 是键到键的映射；`zh-hans.json` 等是英文键到译文的映射。
- 核心词典在 `locales/`；插件和皮肤的特有键放各自的 `i18n/<lang>.json`。
  运行时核心优先、扩展只补缺。
- 新增文案时当场把 25 种语言补齐。`--check` 要求每个语言文件键齐全，缺一条就报错。
- **不要顺手改存量键的措辞**——改一个键等于 25 个文件全动。要改就单独做一次迁移。
- 占位符用 `{:name}`。`{:sitename}` 是全局占位符，运行时自动替换成站点名，调用点不用传参。
- 后台界面固定中文，这是刻意设计：`AdminController` 的展示字段用 `tIn('zh-hans', ...)` 反向翻译，
  后台外壳挂 `zh-hans` 词典。

## 生成与校验

```bash
php docs-internal/i18n/extract.php          # 扫描代码，生成各域的 en.json
php docs-internal/i18n/extract.php --check  # 只检查，不写文件
```

`--check` 是交付前的硬门槛：代码里的键都在词典里、每个语言都齐全、占位符一致。

提取器覆盖这些来源：

- `t()` / `tIn()` 的字面量参数
- `EmailTemplate::render()` 里静态文案字段的值
- 邮件闭包 `$x('...')` 的第一参
- 控制器里的动态常量（登录方式、活动日志动作、家庭关系、恢复方式等）
- 安装向导（`nomen_install_t()`）

提取器**不认变量实参**：`t($labelKey)` 扫不到，会报「核心有、代码里扫不到」。品牌默认链接那几条
要写成字面量。`tIn('zh-hans', $x ?? $y)` 这种第二参带表达式的写法会被当成键，第二参保持纯变量。

规范细节在 `docs-internal/i18n/CONVENTIONS.md`。

## 新增一种语言

1. 在 `locales/` 新建 `<语言>.json`，键齐全（可以从 `en.json` 复制后逐条翻译）。
2. 在 `locales/languages.php` 里补语言名称。
3. 跑 `php docs-internal/i18n/extract.php --check`。

插件 / 皮肤自己的 i18n 目录同样补一份。

## 邮件语言

邮件按收件人的账号语言发；账号没设语言时用站点默认语言，不再固定英文。
涉及 `I18n::emailLocale()`。
