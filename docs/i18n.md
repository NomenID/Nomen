# 多语言

站点界面支持 **25 种语言**（`locales/*.json`），键就是英文原句。切语言不改 URL，走 cookie + 账号偏好。

## 语言是怎么定的

优先级从高到低：

1. `?lang=<code>` 查询参数（兼容入口）
2. 账号偏好（`users.locale`）
3. cookie
4. 浏览器 `Accept-Language`
5. 站点默认（`app.language_default`）

`?lang=` 会写回 cookie，所以下一次不用带。

## 词条格式

```json
{
  "Sign in": "登录",
  "Saved by {:name}": "由 {:name} 保存"
}
```

- **键是英文原句**，不是标识符。译者拿到句子就知道语境。
- **值缺了会回落**：当前语言 → 英文 → 原句。
- **占位符用 `{:名字}`**，`--check` 会核对原文和译文里的占位符一致。
- `{:sitename}` 是全局占位符，自动替换成站点名，调用点不用传。

## 切换入口

| 入口 | 行为 |
|---|---|
| 头部选择器（有 JS） | 下拉，选完跳 `/special/lang?select=<code>&rt=<当前页>` |
| 头部选择器（无 JS） | 普通链接指向 `/special/lang` |
| 移动端抽屉 | 只有 `/special/lang` 一个入口，**首页不带 `rt`** |
| `?lang=<code>` | 直接生效并写 cookie |

`/special/lang?select=en&rt=/login` 会设置语言然后 303 回 `/login`。`rt` 只接受站内路径。

**页面源码里不出现 `?lang=` 链接**（SEO 考虑），`?lang=` 只是兼容入口。

## 后台和邮件

- **后台固定中文**：界面用 `tIn('zh-hans', ...)`，Vue 词典钉死 `zh-hans`。这是有意设计，不是漏翻。
- **邮件跟随收件人的语言**：`I18n::emailLocale()` 按账号偏好 → 站点默认。别硬编码语言。

## 新增词条

```bash
php docs-internal/i18n/extract.php          # 生成/补齐
php docs-internal/i18n/extract.php --check  # 验收
```

`--check` 全绿才算完。它会报：

| 提示 | 意思 |
|---|---|
| `[缺] 代码里有、en 没有` | 新写的键没进词典 |
| `[悬] en 里有、代码里扫不到` | 改了文案但旧键还在，确认后删 |
| `[缺条目] <语言> <键>` | 这份语言文件少了这条 |
| `[占位符不一致]` | 原文和译文的 `{}` 对不上 |

**扫描只认字面量**：`t('Sign in')` 收得到，`t($label)` 收不到。所以文案别用变量拼。

## 加一门新语言

1. 在 `locales/languages.php` 里加语言定义（code、名称、是否 RTL）。
2. 从 `en.json` 复制一份成 `<code>.json`，翻译。
3. `php docs-internal/i18n/extract.php --check`。
4. RTL 语言要确认 `public/css/rtl.css` 覆盖到了。

## 坑

- **改已有键的措辞 = 25 个语言文件全动**。要改就新增键，旧的标悬空后删。
- **`tIn('zh-hans', $x ?? $y)`** 会让提取器把 `'zh-hans'` 当成键，第二参保持纯变量。
- **`t()` 的输出是当 HTML 拼的**（有些键里带 `<a>`），所以文案里的 `+` 之类不会出问题，但插进去的参数要自己转义。
- **页面源码里的 `?lang=`**：改成 `/special/lang` 是为了 SEO，别再往模板里加回 `?lang=`。
- **翻译质量的顺序**：先把中文和英文写对，其余语言机翻后人工过一遍术语。
